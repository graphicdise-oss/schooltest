# ถ้าต้องมี iOS ด้วย — ควรใช้อะไร และต้องเตรียมอะไรบ้าง

**คำตอบสั้น: ใช้ Flutter (หรือ React Native ถ้าทีมถนัดตัวนั้น) เขียนครั้งเดียวได้ทั้ง iOS และ Android**

---

## 1. ทำไมพอมี iOS แล้วคำตอบถึงเปลี่ยน

ทางเลือกที่เคยดู "ง่ายและถูก" จะถูกตัดออกทันทีเมื่อ iOS เข้ามาในโจทย์

| ทางเลือก | พอมี iOS ด้วยแล้วเป็นยังไง |
|---|---|
| Capacitor โหมด Remote URL | ❌ **ตัดทิ้ง** — Apple ปฏิเสธเกือบแน่นอน (Guideline 4.2 Minimum Functionality) |
| Capacitor โหมด Bundled + API | ⚠️ ผ่านรีวิวได้ แต่ **ใช้แรงพอ ๆ กับ Flutter** เพราะต้องทำ API เหมือนกัน |
| **Flutter / React Native** | ✅ **เหมาะที่สุด** — โค้ดชุดเดียวออกได้ทั้ง 2 Store |
| PWA อย่างเดียว | ⚠️ ใช้ได้ฟรี แต่ไม่มีแอปใน App Store และ Push ต้องให้ผู้ใช้ Add to Home Screen เองก่อน |

### เหตุผลหลัก
งานที่หนักที่สุดของทุกทางเลือก (ยกเว้น Capacitor โหมด Remote URL) คือ
**การเปิด API ฝั่ง Laravel** ซึ่งเหมือนกันหมด — เปิด Sanctum, แยก Service,
รวมศูนย์ พ.ศ., ทำ API Resource

พอต้องทำงานก้อนนี้อยู่ดี ความต่างที่เหลือคือ "เขียน UI ด้วย HTML/JS หรือ Dart"
ซึ่ง Flutter ให้ผลลัพธ์ดีกว่าในราคาเท่ากัน โดยเฉพาะกับแอปที่เต็มไปด้วยตาราง
อย่างตารางเรียนและตารางเกรด

> **ถ้าทีมมีพื้นฐาน React Native อยู่แล้ว ให้ใช้ React Native**
> ไม่ต้องเปลี่ยนมา Flutter — ทั้งคู่ทำแอปนี้ได้ครบ ความคุ้นเคยของทีมสำคัญกว่า

## 2. ⚠️ ความเสี่ยงอันดับ 1 ของแอปนี้บน App Store: Guideline 4.2

Apple ปฏิเสธแอปที่ "ทำอะไรได้น้อยเกินไป" หรือ "เป็นแค่เว็บไซต์ในกล่อง"

### แอปผู้ปกครองของเราเข้าข่ายเสี่ยงพอดี
จากโค้ดปัจจุบัน หน้าจอฝั่งผู้ปกครองเกือบทั้งหมดเป็น **อ่านอย่างเดียว**
* ดูผลการเรียน — อ่านอย่างเดียว
* ดูตารางเรียน — อ่านอย่างเดียว
* ดูปฏิทิน — อ่านอย่างเดียว
* ดูข้อมูลติดต่อครู — `parent/contact.blade.php` ไม่มีฟอร์มส่งด้วยซ้ำ อ่านอย่างเดียว
* ประกาศ — อ่าน + กดรับทราบ
* เปลี่ยนรหัสผ่าน

แอปที่แค่ "แสดงข้อมูลจากเว็บ" แบบนี้คือรูปแบบที่ Apple ปฏิเสธบ่อยที่สุด

### สิ่งที่ต้องมี เพื่อให้ผ่าน (ถือเป็นฟีเจอร์บังคับ ไม่ใช่ของเสริม)
1. **Push Notification จริง** — แจ้งเตือนเมื่อมีประกาศใหม่
   (ผูกกับตาราง `announcements` / `announcement_recipients` ที่มีอยู่แล้ว)
   นี่คือฟีเจอร์ที่ทำให้แอปมีเหตุผลที่จะมีอยู่ และเป็นสิ่งที่เว็บทำได้ไม่ดีเท่า
2. **ใช้งานออฟไลน์ได้** — เปิดแอปแล้วเห็นเกรด/ตารางเรียนทันทีแม้ไม่มีเน็ต
3. **เข้าสู่ระบบด้วย Face ID / Touch ID** หลังล็อกอินครั้งแรก
4. **บันทึก/แชร์ไฟล์แนบประกาศ และ PDF ตารางเรียน** ลงเครื่องได้
5. **Widget หน้าโฮม** (ถ้ามีเวลา) — แสดงคาบเรียนวันนี้ เป็นตัวช่วยผ่านรีวิวที่ดีมาก

ถ้ามีครบ 1–4 โอกาสผ่านรีวิวสูงมาก

### ข่าวดี: ไม่มี User Generated Content
ผู้ปกครองส่งเนื้อหาเข้าระบบไม่ได้เลย (`ContactController` และ
`ChangeRequestController` อยู่หลัง middleware `auth` ของบุคลากร ไม่ใช่ guard `parent`)
จึง **ไม่ต้องทำระบบรายงาน/บล็อกเนื้อหา** ตามกฎ UGC ของ Apple
ซึ่งเป็นงานก้อนใหญ่ที่ตัดออกไปได้

## 3. เตรียมบัญชี Apple — เริ่มวันนี้เลย เป็นคอขวดที่ยาวที่สุด

**นี่คืองานที่ควรเริ่มก่อนเขียนโค้ดบรรทัดแรก** เพราะใช้เวลารอนานที่สุด
และไม่มีอะไรเร่งได้

### เลือกประเภทบัญชี

| | บุคคลธรรมดา (Individual) | นิติบุคคล / องค์กร (Organization) |
|---|---|---|
| ค่าใช้จ่าย | 99 USD/ปี | 99 USD/ปี |
| ต้องมีเลข D-U-N-S | ❌ ไม่ต้อง | ✅ **ต้องมี** |
| เวลาที่ใช้ | 1–3 วัน | **2–4 สัปดาห์** |
| ชื่อผู้ขายใน App Store | ชื่อบุคคล | **ชื่อโรงเรียน** |

### คำแนะนำ
สำหรับแอปโรงเรียน **ควรใช้บัญชีองค์กร** เพราะผู้ปกครองจะเห็นชื่อโรงเรียน
เป็นผู้พัฒนา ไม่ใช่ชื่อครูคนใดคนหนึ่ง — สำคัญเรื่องความน่าเชื่อถือ
และเวลาเปลี่ยนคนดูแลจะไม่ต้องย้ายบัญชี

**ขั้นตอน:**
1. ขอเลข **D-U-N-S Number** จาก Dun & Bradstreet — **ฟรี** ขอผ่านหน้าเว็บของ Apple
   ใช้เวลาประมาณ 5 วันทำการ แต่ในไทยมักนานกว่านั้น เผื่อไว้ 2–4 สัปดาห์
   ต้องใช้ชื่อโรงเรียนภาษาอังกฤษและที่อยู่ที่ตรงกับเอกสารราชการเป๊ะ ๆ
2. สมัคร Apple Developer Program ด้วยเลข D-U-N-S
3. Apple อาจโทรมายืนยันตัวตนกับโรงเรียน — ต้องมีคนรับสายและตอบได้

> ถ้าเร่งด่วนมาก: เริ่มด้วยบัญชีบุคคลธรรมดาไปก่อนเพื่อทดสอบ TestFlight
> แล้วค่อยย้ายไปบัญชีองค์กรทีหลังได้ (Apple มีขั้นตอนโอนแอป)

## 4. ต้องมีเครื่อง Mac

**ไม่มีทางเลี่ยง** — การ build, sign และอัปโหลดไฟล์ `.ipa` ขึ้น App Store
ทำได้บน macOS เท่านั้น

| ทางเลือก | ค่าใช้จ่าย | เหมาะกับ |
|---|---|---|
| Mac mini (M4 รุ่นเริ่มต้น) | ~20,000–25,000 บาท | คุ้มที่สุดถ้าจะดูแลแอประยะยาว ✅ |
| MacBook Air มือสอง | ~15,000–20,000 บาท | งบจำกัด |
| Codemagic / GitHub Actions macOS runner | มี free tier / จ่ายตามการใช้ | ทีมเล็ก build ไม่บ่อย |
| Xcode Cloud | รวมอยู่ใน Apple Developer (มีโควตาฟรี) | ใช้คู่กับ Mac เครื่องเดียว |

> พัฒนา Flutter บน Windows/Linux ได้ปกติ แต่ตอนจะทดสอบบน iOS simulator
> และตอนส่งขึ้น Store ต้องใช้ Mac

## 5. Checklist ก่อนส่งรีวิว App Store

### สิ่งที่ Apple บังคับ
- [ ] **บัญชีทดสอบ (demo account)** — แอปบังคับล็อกอิน Apple จะขอรหัสนักเรียน +
      รหัสผ่านสำหรับทดสอบ **ต้องเตรียมบัญชีนักเรียนตัวอย่างที่มีข้อมูลครบ**
      (มีเกรด มีตารางเรียน มีประกาศ) ไม่งั้นรีวิวเวอร์เห็นหน้าว่างแล้วปฏิเสธ
- [ ] **URL นโยบายความเป็นส่วนตัว** — ต้องเป็นหน้าเว็บสาธารณะที่เข้าถึงได้
      (ทำเป็น route ใหม่ในระบบนี้ได้เลย เช่น `/privacy`)
- [ ] **App Privacy label** — ต้องประกาศว่าเก็บข้อมูลอะไรบ้าง
      แอปนี้เก็บ: ชื่อ-นามสกุล, รหัสนักเรียน, ผลการเรียน → เป็น
      "Data Linked to You" ต้องกรอกให้ตรงความจริง
- [ ] **Age Rating** — ตอบแบบสอบถามให้ตรง แอปนี้ไม่มีเนื้อหาไม่เหมาะสม
- [ ] **ภาพหน้าจอ** ทุกขนาดที่ Apple กำหนด (iPhone 6.9" และ 6.5" เป็นอย่างน้อย)
- [ ] **ไอคอนแอป** 1024×1024 ไม่มีความโปร่งใส ไม่มีมุมโค้ง (Apple ใส่ให้เอง)

### ที่ต้องเตรียมคำตอบไว้ (มีโอกาสโดนถาม)
- [ ] **การลบบัญชี** — Apple กำหนดให้แอปที่สร้างบัญชีได้ ต้องลบบัญชีในแอปได้ด้วย
      แอปนี้ **โรงเรียนเป็นคนสร้างบัญชีให้** ผู้ใช้สร้างเองไม่ได้
      → ควรใส่หน้าอธิบายในแอปว่าบัญชีจัดการโดยโรงเรียน พร้อมช่องทางติดต่อ
      และเตรียมอธิบายให้รีวิวเวอร์ในช่อง Review Notes
- [ ] **ทำไมต้องมีแอป ในเมื่อมีเว็บอยู่แล้ว** — ตอบด้วย Push Notification +
      ออฟไลน์ + Face ID (เขียนไว้ใน Review Notes ตั้งแต่แรกเลย ช่วยได้มาก)

### ข่าวดีอีกข้อ
- ✅ **ไม่ต้องทำ "Sign in with Apple"** — กฎนั้นบังคับเฉพาะแอปที่มีล็อกอิน
  ผ่านบริการอื่น (Google/Facebook) แอปนี้ใช้รหัสนักเรียนของโรงเรียนเอง จึงไม่เข้าข่าย
- ✅ **ไม่ต้องทำ In-App Purchase** — แอปนี้ไม่มีการขายอะไร

## 7. ทางลัดถ้างบไม่พอสำหรับ iOS

ถ้าค่า Apple 99 USD/ปี + เครื่อง Mac ยังไม่ผ่านงบ ให้ทำแบบนี้ไปก่อน:

* **Android** → Capacitor หรือ Flutter ขึ้น Play Store (25 USD ครั้งเดียว)
* **iOS** → ใช้ **PWA** ไปก่อน — Safari บน iOS 16.4+ รองรับ
  Add to Home Screen + Web Push แล้ว ได้ประสบการณ์ใกล้เคียงแอปจริงมาก

**ข้อจำกัดที่ต้องบอกลูกค้าตรง ๆ:** ผู้ปกครองต้องกด "แชร์ → เพิ่มไปยังหน้าจอโฮม"
เองก่อน ถึงจะได้รับ Push บน iOS ซึ่งในทางปฏิบัติจะมีคนทำจริงไม่เยอะ
ต้องมีคู่มือ/ป้ายแนะนำที่โรงเรียนช่วย

ถ้าทำแบบนี้ ให้เขียนแอปด้วย **Flutter ตั้งแต่แรกอยู่ดี** เพราะตอนงบพร้อม
จะ build iOS ออกมาได้ทันทีจากโค้ดชุดเดิม ไม่ต้องเขียนใหม่

## 8. สรุป

1. **อยากได้ iOS ด้วย → ใช้ Flutter** (หรือ React Native ถ้าทีมถนัดตัวนั้น)
   โค้ดชุดเดียวออกได้ทั้งสอง Store
2. **Capacitor โหมด Remote URL ตัดทิ้งได้เลย** ถ้าจะขึ้น App Store
3. **เริ่มขอ D-U-N-S และสมัคร Apple Developer วันนี้** — 2–4 สัปดาห์
   เป็นคอขวดที่ยาวที่สุดและทำคู่ขนานกับงานเขียนโค้ดได้
4. **ต้องมี Mac** — Mac mini คุ้มที่สุดถ้าดูแลระยะยาว
5. **Push + ออฟไลน์ + Face ID เป็นฟีเจอร์บังคับ ไม่ใช่ของเสริม**
   เพราะแอปเป็นอ่านอย่างเดียว เสี่ยงโดน Guideline 4.2
6. **เตรียมบัญชีนักเรียนตัวอย่างที่มีข้อมูลครบ** ไว้ให้รีวิวเวอร์ Apple ทดสอบ
7. รวมเวลาประมาณ **10–13 สัปดาห์**
